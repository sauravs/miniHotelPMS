# ui/ — the product surface

A Next.js UI over the engine's read-only JSON API. It is **not part of the engine**: nothing in
`hotelcontrols/` imports it, and the engine ships, audits and demos with this directory deleted.
The server-rendered pages the engine serves itself stay. They are the offline, printable audit
surface (`docs/prd.md` §6).

## Run it

```bash
python3 -m hotelcontrols.web.server      # the engine, :8765
cd ui && npm ci && npm run build && npm start   # this UI, :3000
```

`HOTELCONTROLS_API_URL` points the UI at the engine. It defaults to `http://127.0.0.1:8765`.

## How it is built, and why

- **The browser never talks to the engine.** Data is fetched in Server Components through one
  module, `lib/api.ts`. The engine's stylesheet comes through a rewrite on this origin. So no
  CORS header exists anywhere, and the engine's CSP is untouched.
- **A run is a POST, then a redirect.** `GET /api/run/` spends provider calls and writes the store.
  The Run button is a Server Action. It runs once, then sends the reader to `/runs/<run_id>`, which
  re-reads the stored run for free and can be reloaded, prefetched and bookmarked.
- **One stylesheet for both surfaces.** The markup uses the engine's class names, and
  `/style.css` is the engine's own file. So the criterion-2 rules (four hues, four border styles)
  have one source, which the Python suite already parses.
- **One source of wording.** Badges and meanings come from `/api/outcomes`, which serves the
  engine's `WORDING`. They are never typed here.
- **A real CSP** (`proxy.ts`): scripts only with this request's nonce, nothing inline, nothing
  from another origin, no framing.

## Tests — no engine process, no socket, no run ever triggered

| Layer | Where | What |
| --- | --- | --- |
| Golden payloads | `../fixtures/api/` | Generated by `tools/dump_api_fixtures.py`, never edited. The contract. |
| Components | `test/*.test.tsx` (Vitest) | Criteria 2 (wording, styles stripped), 3, 8, glossary, grouping |
| Parity | `test/parity.test.tsx` | Every golden, live and stored. No record is dropped, duplicated or mis-grouped, every evidence line appears verbatim, and tiles appear exactly when the run concluded. |
| Real browser | `e2e/` (Playwright) | Four computed border styles and four hues, keyboard reachability, and axe on each run state. The page is rendered from goldens with `setContent`, with no server. |
| Required Python | `../tests/unit/test_ui_hygiene.py`, `test_canonical_boundary.py` | No parsing of money, no PMS identifier, no injected HTML, one requesting module, exact pins |

```bash
npm test          # vitest
npm run e2e       # playwright (first time: npx playwright install chromium)
npm run typecheck
```

## Dependencies — every one justified

Pinned exactly (`.npmrc` `save-exact`), with the lockfile committed. Adding a runtime dependency
means editing `test_trap_7_the_runtime_dependency_list_stays_short`, on purpose.

| Package | Kind | Why it is here |
| --- | --- | --- |
| `next`, `react`, `react-dom` | runtime | The stack of the superset product this converges with (brief §0) |
| `typescript`, `@types/*` | dev | Types for the API contract (`lib/types.ts`). Pinned at 6.x, the last JavaScript release, which Next's type-check uses. |
| `vitest`, `vite` | dev | Component tests. `vite` is a peer of `vitest`. |
| `@testing-library/react`, `@testing-library/dom`, `jsdom` | dev | Rendering components without a browser |
| `@playwright/test` | dev | The only honest way to assert computed styles (criterion 2) |
| `@axe-core/playwright` | dev | The accessibility pass per page state |

jsdom 30 needs Node ≥ 22.22.2, so that is the `engines` floor. Next's telemetry is switched off
in every script: this product does not phone home.
